# GOLDENHEADS — notas para Claude

Juego web **HEADS Rescate Dorado** de Santi: un astronauta dorado defiende su nave de arañas rojas. El juego es de Santi y solo usa el nombre y el logo de HEADS. Habla con Santi en español.

## Dónde está cada cosa
Desde v61 el proyecto se compila con Vite (`npm run build` → `dist/`). Desde v85 el juego vive en **Cloudflare Workers**, en https://goldenheads2021.com/headsrescue/: `npm run build:cf` = `vite build` + `tools/cloudflare/make-site.mjs` → `site/` (lo que publica Cloudflare: `site/headsrescue/` = `dist/`, más `site/_headers` y `site/_redirects`), y el servidor (`/api/*`) es un Worker (`worker/`, `wrangler.jsonc`). Ver «v85» más abajo.
- **Rutas: todas relativas salvo `/api`.** El mismo `dist/` funciona en la raíz (pruebas, `npm run dev`) y en `/headsrescue/`: ningún archivo propio se pide con `/` delante (ni en `index.html`, ni en el código, el CSS, `public/*.js`, las listas de `public/assets/`, `admin.html`, las páginas de privacidad o el manifiesto); las listas de `ui/` siguen dando URL absolutas, pero calculadas con `document.baseURI`. Solo la API va siempre a la raíz del sitio: `/api/...`. Lo comprueba la prueba `subpath`.
- `index.html`: el marcado de la página.
- `src/game/NN-nombre.js`: el código del juego en piezas (43 desde v83). Comparten un solo ámbito: el plugin `heads-game` de `vite.config.js` las concatena por orden de nombre, igual que el antiguo `<script type="module">` único. No uses `import`/`export` entre piezas; una pieza nueva va con el número que le toque.
- `src/styles/NN-*.css`: el CSS en el orden de cascada original (los importa `src/main.js`).
- `src/hud/hud.js`: HUD de móvil de Santi (v62, todo por código, `window.HUD`); lo conecta `src/game/32-hud-movil.js` y solo se monta en táctil.
- `public/i18n.js`: script clásico que corre antes del juego (bloque i18n ES/EN, selector de idioma y menú de PC). three.js viene de npm (versión fija 0.170.0).
- `public/menusfx.js` (v70): `window.menuSfx(nombre)`, ruidos mecánicos de los menús de PC y móvil. Desde v73 son **siete** sonidos (clave → archivo en `public/assets/sfx/menu/`, tabla `FILES` al principio de `menusfx.js`): `logo`, `land`, `bar` y `button` (sintetizados con `tools/menu-sfx/synth_menu_sfx.py`), y **tres grabaciones de Santi**: `unfold` → `metro.mp3` (cinta métrica que se extiende: el panel se despliega), `lock` → `arma-juguete.mp3` (pistola de juguete que se amartilla: el panel se encaja) y `decode` → `decoder.mp3` (decodificador de texto: los títulos del menú). Esos tres NO son sintéticos y el script ya no produce `unfold` ni `lock`: no lo regeneres encima. `decode` empieza con el primer título que se decodifica (PC: `startMenuIntro` en `public/i18n.js`, 1,64 s; móvil: `MM_CUES` en `30-hud4-menus.js`, 1,9 s, donde entran los textos) y, como dura 1,5 s y el texto tarda ~1 s, se baja con `menuSfx.fade('decode',0.15)` cuando termina el texto. Suenan flojos (master 0.35), solo después de un gesto del usuario (si no, se saltan) y se cierran al pulsar JUGAR. Prueba: `tools/run-test.sh dist tools/tests/menu-sfx.cjs` (con la compilación real: la de prueba se salta el selector de idioma).
- Música (v73): `public/assets/music/menu.mp3` (tema 1, 51,5 s, cosido para repetirse sin corte) y `public/assets/music/game.mp3` (mezcla DJ 1→2→3→4→5→1 de los temas de Santi, 7:12, −16 LUFS, cosida para repetirse; datos de cada transición en el doc de diseño). Menú: `window.menuMusic(true|false)` en `public/menusfx.js`; el mp3 se decodifica con los efectos (60 s ≈ 21 MB de PCM), empieza con el primer gesto del usuario (antes no hay AudioContext: silencio), entra en 1,5 s a nivel bajo (`MUSIC_VOL` 0,16), se apaga en 0,8 s al pulsar JUGAR y nunca suena sobre la película de apertura (que empieza justo después de JUGAR). Juego: bloque «music» al final de `src/game/19-audio.js` (`MUSIC`, `musicStart/musicEnd/musicHold/musicTick`): un `<audio>` en streaming (nunca decodificado entero) que pasa por `createMediaElementSource` → `musicGain` → `master` (iOS ignora `el.volume`); nivel `MUSIC.vol` 0,22; baja a ×0,3 (`duckTo`) mientras habla una voz (`VOQ.until` + 0,3 s); `musicStart()` va dentro del clic de JUGAR/REINTENTAR (`27-opening.js`, `26-ranking.js`), `musicEnd()` en `endGame`, `musicHold()` en la pausa del móvil. La música procedural antigua ya no existe (sin plan B si el archivo falla). Prueba: `music`.
- `public/assets/`: archivos reales (`models/*.glb`, `sfx/`, `music/`, `vo/es`, `vo/en`, `ui/<kit>/`, `opening.mp4`). Los `.js` de esa carpeta son listas con las mismas claves de antes; las de `ui/` dan URL absolutas porque algunas acaban en variables CSS.

## Cómo publicar
- Este repositorio es la versión buena. Las carpetas antiguas `F:\AI\HEADS\JUEGO\game` y `web` quedan como copia.
- Push a `main` = publicación en **https://goldenheads2021.com/headsrescue/** (Cloudflare **Workers Builds**, conectado a este repositorio: comando de compilación `npm run build:cf`, de despliegue `npx wrangler deploy`). `goldenheads2021.com/` lleva de momento a `/headsrescue/` (302).
- Trabaja en una rama. Cada push a otra rama sube una **versión de prueba** (`npx wrangler versions upload`, sin tocar la web pública) con su enlace en workers.dev (`<versión o rama>-goldenheads.<subdominio>.workers.dev`; sale en el panel de Cloudflare y en el commit de GitHub). Como las vistas previas de Netlify: guarda solo partidas y métricas de prueba y su ranking enseña solo esas (todo host que no esté en `PROD_HOSTS` es vista previa). Pasa a `main` solo cuando Santi lo apruebe.
- Plan gratuito de Workers: 100.000 peticiones al Worker al día. Solo cuentan `/api/*` y los dos archivos que se sirven por trozos (`assets/opening.mp4`, `assets/music/*`); todo lo demás son archivos estáticos, gratis y sin límite.
- Variables (Workers & Pages → goldenheads → Settings → Variables and Secrets; valen para el sitio real y para las versiones de prueba): `SUPABASE_URL` y `SUPABASE_PUBLISHABLE_KEY` como texto, `SUPABASE_SECRET_KEY`, `RANK_SECRET` y `ADMIN_PASSWORD` como secretos. `keep_vars: true` en `wrangler.jsonc`: un despliegue nunca las borra. `PROD_HOSTS` sí está en `wrangler.jsonc` (no es secreta).
- Netlify ya solo redirige: `netlify.toml` publica una carpeta de un archivo y manda toda dirección de heads-rescate-dorado.netlify.app a la misma en `https://goldenheads2021.com/headsrescue/` (301, con la consulta; `/api/*` a `https://goldenheads2021.com/api/*`). Cuando esa redirección esté publicada, se pueden parar las compilaciones de Netlify (Build settings → Stop builds) para no gastar créditos en cada push a `main`; mientras sigan activas, `[skip netlify]` en el mensaje del commit evita una compilación.
- Firma los commits como `Shorttheboch <174453569+Shorttheboch@users.noreply.github.com>`.
- Ninguna clave en el repositorio (ni la URL ni la clave publicable de Supabase): las cinco van solo en la configuración del Worker y el navegador recibe la URL y la clave publicable por `/api/auth`. Para probar el Worker en local, `wrangler dev` con un archivo de variables fuera del repositorio (`--env-file`; `.dev.vars*` está en `.gitignore`).
